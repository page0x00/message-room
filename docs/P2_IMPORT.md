# 2.3 · 批量截图与留言多选

## 使用

在聊天输入框的 `＋` 中打开截图导入。主按钮优先请求**只读**目录，可递归读取子目录；无法使用目录选择时转为多文件选择。旁边始终保留“多选截图文件”。Android 上目录 API 不可用时直接使用文件多选入口；系统文件选择器的外观由浏览器与系统决定。

队列按截图文件名中的日期/时间排序，没有可解析时间时使用文件修改时间。支持全选、反选、只选新截图、默认跳过已处理截图。SHA-256 按图片内容去重，改名后的同一文件也能识别。队列与草稿每页显示 20 项，不限制总张数；单张 JPG/PNG/WebP 最大 80 MB。大量图片逐张处理，停止后保留已完成的部分，失败文件可重试。

完整聊天截图直接识别，不要求手动裁剪。长图自动切成有重叠的片段，保留文字分辨率；先定位气泡并排除头像、状态栏、标题栏和底部输入区域，再做 OCR。跨片的同一气泡按位置合并和去重，日期/时分分隔行单独解析。绝对日期优先，相对日期按截图日期推算；图中没有聊天日期时明确标为“截图日期（未见聊天日期）”，不能据此断言真实聊天日期。

预览可改正文、左右方向、称呼和显示日期，可只发送左侧、只发送右侧，或按日期合并为可展开的记录。低置信度文字提示核对，较低置信度项默认不选。原图不上传；确认后只发送选中的摘录，可另补原媒体。显示日期与真实创建时间分开保存。

在消息上长按、电脑右键或键盘 Enter 进入多选，底部可引用、合并转发、逐条转发、收藏、复制和删除；选中自己的单条邀请房间消息可修改显示日期。引用最多 8 条。转发目标为已加入房间，附件复制到目标房间的私有路径。收藏与删除记录按当前浏览器、房间和身份保留；删除是**本机隐藏**，房间菜单“最近删除”可恢复，不删除对方或云端记录。

## 保存与失败恢复

- 识别队列、草稿、处理记录和发送编号保存在本机 IndexedDB；文字编辑还有同步暂存，防止编辑后立即刷新丢失最后一次修改。原文件只在当前页面内存，刷新后需要重新选择原文件才能再次识别或预览。
- 邀请房间复用持久化的消息 nonce，部分成功后只继续未完成部分。上次发送未确认时锁定该批次正文与发送方式，避免改变内容后误重发。全部成功后可开始下一批。
- 老房间无法提供服务器端 nonce 去重；未确认送达时保留进度并要求先核对聊天，不自动重复投递。
- 跨房间的延迟响应只更新原房间进度，不写入当前房间草稿。
- 清空当前队列不删除已经发送的留言或已处理图片记录。清除网站数据会丢失本机记录。

## 验证边界

真实 OCR 测试使用 Tesseract 中英文模型，覆盖浅色/深色完整长图、三个分片、跨片长气泡、左右方向和两处日期分隔行。浏览器集成测试的 OCR 输出是夹具，专门验证队列、目录回退、选择、编辑、确认、去重和重试；不把夹具结果当作真实识别质量。

本轮另以用户提供的完整微信截图做本机识别：拆出 16 条，7 条左侧、9 条右侧，提取时分，没有混入标题、头像和输入栏。个别短语仍可能误识别，必须在可编辑预览核对；截图本身没有完整聊天日期，不凭空补造。用户截图、识别文本和私人测试素材没有加入仓库。

真实 OCR 检查可复现：先运行 `npm ci`，将 `chi_sim.traineddata.gz` 与 `eng.traineddata.gz` 下载到忽略的 `test-results/ocr-models/`，然后执行 `npm run test:ocr`。模型地址与生产配置相同：`https://tessdata.projectnaptha.com/4.0.0/`。测试会生成自己的完整聊天图，不需要私人素材。

端侧待验收：Android/iOS 原生文件选择器、真实超大量/超长图的内存与后台中断、不同聊天应用及字体壁纸的识别质量，以及生产 Supabase 双设备收发。目录 API 存在浏览器差异，页面始终保留多选入口。

## Supabase

本次升级复用已有消息字段、私有 Storage 和 RLS，无新增线上迁移。已完成 2.2 配置的项目直接更新前端。尚未配置的项目按 [SETUP.md](../SETUP.md) 执行完整增量 SQL、匿名 Auth；离线 Web Push 仍需部署 Edge Function、配置 VAPID Secrets 和消息 INSERT webhook。前端不包含私钥。
