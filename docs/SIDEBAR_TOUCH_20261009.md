# 2.7.4 · 侧栏触屏响应

旧侧栏只监听 `click`。在浏览器未补发兼容 click 的触屏路径中，按钮可见、指针事件也正常，但页面不跳转。新增浏览器回归通过取消侧栏 `touchstart` 的默认行为复现这一条路径：禁用修复时点击「对话」仍停在首页，启用后立即进入对话。此为自动化复现，尚未在用户的 vivo Pad Air 上直接验收，不能据此断定设备上的全部成因。

## 修改

- 侧栏导航、展开/收起与主题按钮响应单指/笔的 `pointerup`，随后生成的原生 click 去重。鼠标、键盘和辅助技术的 click 仍可正常使用。
- 手势必须从真实命中的按钮开始并在同一按钮结束；移动超过 14 CSS 像素、滚动、取消、失去捕获、第二根手指加入及弹窗遮挡均不会触发导航。不按坐标穿透遮罩。
- 页面内容与侧栏分别建立层叠上下文，内容里的画布、变换和高层级元素不能盖住侧栏；真正的弹窗继续位于整个应用上方。
- 浏览器入口及模块依赖统一更新为 2.7.4，保留现有六套主题的布局与数据。

## 验证

- 导航 7 组：缺失 click、普通触摸只响应一次、拖动/取消/双指、弹窗隔离、Enter/Space、折叠状态与重复切页；六主题 × 四尺寸（390×844、820×1180、1536×864、844×390）检查真实命中及页面跳转。
- 启动 8 组：无房间入口、历史房间恢复、延迟登录不抢导航、六主题首次加载一致、错误重试与账号隔离。
- 触屏布局 7 组：空间滚动、信箱进入对话、两种软键盘缩放模式、回忆墙浮动工具与线索板拖动。
- 64 项单元测试和 JavaScript 语法检查通过。

所有浏览器测试使用隔离的模拟账户并拦截后端请求，不写入真实房间。
